# T7.1 — `src/internal/list-projection.ts`

**Phase** P7 — Sortable list · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

Answer "where would this item land, and how far does every other item shift?" as **pure
math over cached rects** — computed once per store-state version and read by O(1)
selectors, never recomputed per subscriber (perf invariant 9).

## Test first

Red tests before implementation, on hand-built rect fixtures:

- Item order is derived from cached rects along the list axis, for both `vertical` and
  `horizontal`.
- Projected index of the active item, including the two ends and the no-op case (dragging
  an item onto itself projects its own index and produces zero translates).
- Per-item translate: items between the origin and the projection close the gap; the rest
  don't move. Assert exact values, not just signs — an off-by-one here is a visible
  stutter.
- Items of **unequal size** produce correct translates (equal-height fixtures hide the
  most common bug in this math).
- **Memoization:** calling the projection twice with the same state object returns the
  **identical reference** and recomputes once; a new state object recomputes. This is the
  test that protects perf invariant 9 — a WeakMap keyed by the immutable state object from
  [T3.1](T3.1-store.md).

## Acceptance criteria

- Pure: no DOM, no React, no `'use client'`.
- Memoized once per store-state version via a WeakMap keyed on the state object; per-subscriber
  reads are O(1).
- **The WeakMap key must be the per-provider store state object — never consumer-supplied
  data** (the `items` array, a node, a props object). The memo map is module-level, so an
  identity shared across two `DndProvider`s would make them overwrite each other's entry:
  last writer wins, and the symptom is a wrong projection in whichever provider rendered
  second. Store state objects are minted per provider and cannot collide; consumer arrays
  can and do. This is exactly the slate-react `NODE_TO_PARENT` bug — same global registry,
  same identity collision, same silent corruption. See [`ANALYSIS.md`](../ANALYSIS.md) § A5.
- **Regression test:** render the *same* `items` array into two sibling providers, drag in
  both, assert each gets its own correct projection.
- Handles both list directions; direction comes from the `SortableList` context, not a global.
- Named constants for any threshold.
