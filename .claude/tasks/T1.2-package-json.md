## Goal

The manifest that encodes the library's hard constraints: ESM-only, zero runtime
dependencies, **no root entry point**, and an explicit subpath `exports` map that
makes deep imports into `src/internal/*` fail at resolution time rather than in review.

## Test first

Not applicable directly — but this task is verified by machine, not by eye:
[T1.6](T1.6-install-green.md) proves the scripts run and [T9.4](T9.4-build-and-package-checks.md)
proves `publint` + `attw --profile esm-only` are clean against the emitted `dist/`.

## Acceptance criteria

- `"type": "module"`, `"sideEffects": false`, `"files": ["dist"]`, `"license": "MIT"`.
- `exports` lists **one entry per public subpath** from the `CLAUDE.md` module map
  (`./dnd-provider`, `./use-draggable`, … `./types`) plus `"./package.json"`, each with
  `types` before `default`. **No `"."` root entry** — that is ground rule 4.
- Nothing maps into `dist/internal/`.
- `peerDependencies`: `react` and `react-dom` at **`>=19.0.0`** (decided by the user,
  2026-08-08 — [`ANALYSIS.md`](../ANALYSIS.md) § A8). A peer range is a *support statement*:
  declaring `>=18` while testing only on 19 would be a lie in the manifest. Consumers on 18
  can override peers at their own risk; we don't claim it.
- `devDependencies` install React 19 (`react` / `react-dom` `^19.x`, matching the A3-cited
  line), `@types/react` 19, and a React-19-compatible `@testing-library/react` (≥ 16.1).
- No `dependencies` — ever.
- `"workspaces": ["playground"]` (bun workspaces; replaces `pnpm-workspace.yaml`).
- No `packageManager` field pinning pnpm.
- **`bunfig.toml` with `[install] linker = "isolated"`** — committed, not optional.
  Bun's *default* is a hoisted `node_modules`, which makes phantom dependencies
  resolvable: a stray `import` of a transitive dep would typecheck and pass tests here,
  then fail for consumers. pnpm's layout prevented that structurally; the isolated linker
  restores it. Verified on bun 1.3.5 — under `--linker=isolated`, a transitive dep is
  neither hoisted to the top level nor resolvable from the root. This is what keeps the
  "zero runtime dependencies" claim honest at develop time rather than only at
  [T9.4](T9.4-build-and-package-checks.md).
- Scripts, exactly matching `CLAUDE.md` § Commands:
  - `build` — clean `dist/`, `tsc -p tsconfig.build.json`
  - `typecheck` — `tsc --noEmit`
  - `test` / `test:watch` — `vitest run` / `vitest`
  - `check` / `check:fix` — `biome check .` / `biome check --write .`
  - `check:package` — `publint && attw --pack . --profile esm-only`
  - `verify` — typecheck → check → test → build → check:package
- `verify` chains with `bun run <script>`, not `pnpm <script>`.

## Where it stands

Written fresh (2026-08-08). `package.json` + `bunfig.toml` on disk; `bun install` clean,
`bun.lock` committed. All criteria above hold.

Two things worth knowing for whoever reads this next:

- **`"workspaces": ["playground"]` made `bun install` fail** with
  `error: Workspace not found "playground"` — bun resolves workspaces eagerly, so the
  directory has to exist. A minimal `playground/package.json` (`name: "playground"`,
  `private: true`, `type: "module"`) was committed as the seed
  [T9.5](T9.5-playground-app.md) builds on. It is a stub, not the app.
- **The isolated linker was verified, not assumed.** `node_modules/` has exactly the 10
  direct devDependency entries, and `require.resolve('scheduler')` — a transitive dep of
  `react-dom` — throws from the repo root. Phantom dependencies are unresolvable, which is
  what keeps the zero-runtime-dependency claim honest at develop time.

`@testing-library/dom` is a devDependency in its own right: `@testing-library/react` 16
declares it as a peer rather than bundling it, and under the isolated linker an unlisted
peer is genuinely unresolvable rather than accidentally hoisted into place.

Installed versions: bun 1.3.5, Biome 2.5.7, TypeScript 5.9.3, Vitest 3.2.7, React 19.2.8 —
the last being the exact version [`ANALYSIS.md`](../ANALYSIS.md) § A3 cites line numbers
against.
