# T4.4 — `src/use-active-drag.ts` + `src/use-dnd-monitor.ts`

**Phase** P4 — React API · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

Two ways to observe a drag from anywhere in the subtree: `useActiveDrag` for components
that want to *render* from the active drag, and `useDndMonitor` for components that want
to *react* to it without re-rendering at all.

## Test first

Red tests before implementation:

- `useActiveDrag` re-renders on start and end, and **not** per move — unless the consumer
  selects something that changes per move. Render counter asserts it.
- `useDndMonitor` causes **zero** re-renders in its host component while firing on every
  event — that's the entire point of it existing alongside `useActiveDrag`.
- Listeners are read through a latest-ref, so passing new inline closures each render
  does not resubscribe on every render.
- Unsubscribes on unmount; StrictMode leaves exactly one subscription.
- Both throw the named out-of-provider error from [T3.3](T3.3-context.md).

## Acceptance criteria

- `useActiveDrag` exported at `fc-react-dnd/use-active-drag`.
- `useDndMonitor` + `DndMonitorListeners` exported at `fc-react-dnd/use-dnd-monitor`,
  covering start / move / over / end / cancel.
- Monitor listeners fire **before** state reset on end/cancel, matching
  [T3.1](T3.1-store.md) — a listener reading the drag during `onDragEnd` sees it.
- `'use client'` at the top of both.
