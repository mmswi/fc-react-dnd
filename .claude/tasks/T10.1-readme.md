# T10.1 — `README.md`

**Phase** P10 — Docs & the artifact · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

The page someone lands on. It has one unusual thing to explain up front — there is no root
entry point, so `import { useDraggable } from 'fc-react-dnd'` does not work and never will —
and one thing to lead with: the tree case.

## Acceptance criteria

- **Requirements stated up front: React 19+** (peer `>=19.0.0` — § A8; no 18 claims
  anywhere in the document, including examples and SSR notes), ESM-only.
- Install, then a quickstart that **imports from subpaths** (`fc-react-dnd/use-draggable`),
  with a sentence explaining why there is no root entry.
- Per-subpath API reference matching the `CLAUDE.md` module map exactly — every public
  export documented, nothing documented that isn't exported.
- A tree section that is the centrepiece, not an appendix: drop-into vs drop-between, depth
  projection, cycle prevention, and the fact that the math is pure and independently usable.
- Accessibility section: keyboard controls table, announcements, the `accessibility` prop —
  plus the tree recipe: `aria-level` / `aria-posinset` / `aria-setsize` on rows and
  overriding the projection-driven announcement texts (§ A7 F9).
- Documented consumer contracts, each with its failure mode: `items` (and `canNest`) must be
  referentially stable (§ A7 F6 — inline literals defeat the projection memo); collapse
  state is restored after the drag, never mid-drag (§ A7 F8 — mid-drag restoration cancels
  the drag); lists keyed by id, not index (§ A6 case 5).
- Performance section: the store-outside-React idea and the render-count numbers from
  [T9.6](T9.6-chrome-qa-and-profiler.md) — measured, never estimated.
- SSR / RSC notes: which modules are server-importable (the directive-free ones) and which
  require `'use client'`.
- **Every code example compiles against the current API** — check it, don't eyeball it.
  This is release checklist item 2.

## Where it stands

`README.md` on disk (2026-08-08). Every criterion above met, including the two that are easy to
claim and hard to hold.

### "Every code example compiles" — checked, not eyeballed

The four self-contained code blocks were extracted from the Markdown into a scratch project whose
`paths` map `fc-react-dnd/*` at `src/*`, and compiled with the repo's own TypeScript. Exit 0. The
three remaining blocks are a bare projection literal, the deliberately-invalid root import, and a
two-line good/bad `items` contrast — none of them compilable units, by design.

### "Every public export documented, nothing documented that isn't"

Checked by script against `package.json#exports` and the `export const|type|function` lines of
every public module. The first pass found **25 exports** hiding behind an ellipsis in the `types`
and `tree` rows; both rows are now exhaustive — 31 and 14 names. Undocumented: none. Documented
but non-existent: none.

### Performance numbers

Straight from [T9.6](T9.6-chrome-qa-and-profiler.md)'s browser capture, with the scenario stated
alongside them so a reader can re-run it: 24 items, 154 px, 3 boundary crossings, 40 pointermove
events, per-row `<Profiler>`, three identical runs. **4 rows / 9 commits** against dnd-kit's
**24 rows / 96 commits**. Measured, never estimated — and the number agrees with
[T7.4](T7.4-sortable-granularity-tests.md)'s jsdom assertion exactly.

### What the document leads with

The tree, in the second paragraph, as a projection object rather than a claim. The rest of the
structure follows the criteria: no-root-entry explained before the first import, then quickstart,
then trees as the centrepiece rather than an appendix, then the API table, accessibility with the
keyboard table and the tree `aria-level`/`posinset`/`setsize` recipe, the three consumer contracts
each with its failure mode, the concurrent-edit policy, performance, and the SSR/RSC list of the
three directive-free modules.

The A2 correction is respected throughout: the competitive claim is the narrow verified one —
every general-purpose library reports a **gesture relative to one row** and none computes the
resulting position — and never the falsified "nobody supports trees".
