# T11.8 — The readability rewrite: fewer hops, straighter implementations

**Phase** P11 — Defects found after v0.1 · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

Make `src/` readable by tracing, not by simulating. The user, after reading the library:

> I don't have to do mental gymnastics in order to understand what the library does. the
> implementations need to be straight forward and easy to follow. you need to avoid so many hops
> between files, because it is hard to follow

This promotes the two sections [T11.7](T11.7-navigational-comments-and-activate-rename.md) declared
out of scope — "flattening the re-entrant hop" and "decomposing `store.ts`" — both of which that
file left as *a design decision for the user, not a side-effect of a comment pass*. The user made
that decision on 2026-08-11.

## Scope, as decided with the user (2026-08-11)

| Question | Decision |
| --- | --- |
| Public API | **Unchanged.** Same 13 subpaths, same exported names and types. Restructuring stays inside module bodies and `internal/`. |
| `internal/` layout | **Free to change** — merge, split, delete, relocate. |
| `store.ts` (571 lines, 29 methods, 6 shared mutables) | **Restructure**, into registries / measurement / lifecycle / session, with one explicit state holder. |
| Comments (1113 lines, 31% of `src/`) | **Compress in place.** Keep every fact, cut the argument; rewrite essays to the spoken-need form. Nothing relocated to another file — that would add the hop the task exists to remove. |

## The red test

A pure refactor has no new behaviour, so the guard is the thing that must not change:
`src/public-api.test.ts` pins the runtime export surface of every one of the 13 public subpaths,
by name. Red first (seeded with a name the module does not export), then green — after which any
step in this task that accidentally moves the public surface fails the gate immediately rather
than at `check:package` or in a consumer's codebase.

The existing suite is the second net, and the stronger one: **510 tests across 34 files, green at
`618a9ad`.** No assertion may be edited to accommodate this task.

## The hops to remove

1. **The re-entrant sensor hop.** `use-draggable.ts:112` → `handle-props.ts:55` mints
   `beginDrag: (init) => store.beginDrag(id, init)` → `pointer-sensor.ts` calls it → back into a
   file the reader already closed → `store.ts` `beginDrag`. Minting the closure at its call site
   collapses this to two files. **Verified API-neutral**: `Sensor` and `SensorContext` in
   `types.ts` are untouched by it.
2. **`store.ts`.** No method reads in isolation, because all 29 close over the same 6 mutable
   variables.
3. **Micro-modules judged by hop cost, not line count.** A module whose name fully predicts its
   content (`keys.ts`, `node-style.ts`) costs zero hops — the reader never opens it. Only modules
   you must open to follow control flow are in scope. Inlining `node-style.ts` into its three
   consumers would break DRY for no navigational gain.

## Acceptance criteria

- `src/public-api.test.ts` pins all 13 subpaths; fails before the surface is pinned, passes after.
- Every existing test assertion is byte-identical. A test **file** may move when its module is
  merged (colocation requires it); its assertions may not change.
- Tracing "what happens on pointerdown" no longer re-enters a closed file.
- No rationale **fact** is lost — only the argument around it. The A6 removal policy, the
  ref/effect split (§ A9.4), the snapshot-cache infinite-loop hazard, and the StrictMode
  attach→detach→attach ambiguity all still state their why at the code that implements them.
- These stay, and stay explained — each looks like an optimisation and is not:
  WeakMap-per-state-version memoisation (perf invariant 9), `use-store-selector`'s snapshot cache
  (an uncached selector is an infinite loop), the ref/effect registration split, and
  `pendingRemovals` + `queueMicrotask`.
- `bun run verify` green.
- `mihai-coding-standards` closing checklist walked against the diff.

## Where it stands

**Done, 2026-08-11.** `bun run verify` green end to end (typecheck → Biome 83 files → 528 tests →
build → publint/attw "All good!"). Baseline was 510 tests / 34 files at `618a9ad`; the 18 added
are `src/public-api.test.ts`. **No existing test was edited.** Not committed — the user's call.

What landed:

1. **The re-entrant sensor hop is gone.** `internal/handle-props.ts` → `internal/drag-handle-props.ts`,
   which no longer imports the store at all: callers pass a ready `SensorContext`, so
   `beginDrag: (init) => store.beginDrag(id, init)` now reads at its own call site in
   `use-draggable.ts` and `use-tree-drop.ts`. Verified API-neutral — `Sensor` and `SensorContext`
   are untouched. Backlinks added at both invocation sites in the sensors.
2. **`store.ts` reordered by lifecycle**, every function defined before it is used, so no forward
   references and no `function`-declaration hoisting. `beginDrag` was defined inline inside the
   returned object literal; it is now a named `const` beside `endDrag`/`cancelDrag`, and the
   return is a flat manifest. `cancelDrag` became an arrow like everything else. Section banners
   separate **what React reads** (`state`, replaced wholesale — the identity the projection
   memoisation keys on) from **private bookkeeping** (mutated in place). Merging all six mutables
   into one object was considered and rejected: it would erase exactly that distinction.
3. **`projectTreeDrop`: 118 lines → 33.** The four projection literals became named builders
   (`nestInto`, `dropAboveFirstRow`, `dropAsFirstChildOf`, `dropAfterSubtreeOf`), the depth
   clamping became `allowedDepthRange`, and `resolveTarget` returns a discriminated `DropTarget`
   instead of `{ intoRow, gap }` where one half was always dead.
4. **Comment pass**, 1113 → 1100 lines net. That number understates it: ~58 lines of
   argument-shaped prose were compressed away, offset by +39 lines of navigation banners and
   backlinks in `store.ts` and +6 doc lines on `tree.ts`'s new named steps. Total `src/` lines
   went **up** (4140 → ~4200) — extracting named functions costs signatures and buys the reader
   smaller units to hold.
5. **Two name collisions fixed**, both absorbed from T11.7: `pointer-sensor.ts`'s internal
   `activate` → `promoteToDrag`, and `keyboard-sensor.ts`'s local `beginDrag` (which called
   `context.beginDrag`) → `pickUp`.
6. Incidental defects: `internal/geometry.ts` had **two consecutive JSDoc blocks on one constant**,
   so the first was orphaned and invisible — merged. `tree-drop-indicator.tsx` hard-coded its blue
   twice in two formats — now named constants.

Deliberately not done, with reasons:

- **`store.ts` was not split across files.** The user's preview sketched four modules, but all 29
  methods close over the same mutable state, so splitting requires threading a context bag through
  every module — strictly more indirection, against the task's own top goal. Reordering in place
  got the readability without it.
- **The two projection caches still duplicate their two-level WeakMap.** They differ in their
  options comparator, so the shared helper would need one injected — a factory returning a
  function, which is the shape the user complained about. The duplicated *essay* was compressed
  instead.
- **Module-private duplicate names left alone** (`CacheEntry`, `computeProjection`,
  `projectionCache` in the two projection files; `NO_DATA` in three). None is importable, and the
  symmetry is a feature when comparing two parallel implementations.

Found and escalated: [T11.9](T11.9-tree-drop-indicator-name-collision.md) — `TreeDropIndicator` is
exported both as a type (`tree.ts`) and as a component (`tree-drop-indicator.tsx`). A breaking
rename, so it could not land under this task's API-identical constraint.

Relationship to T11.7: it stays open for the remaining backlinks at the seams it lists
(`store.ts` `subscribe`/`addMonitor`/`createSession`, `use-draggable`'s ref/effect split) and its
`backlinks.test.ts` guard. Its two renames are done here; its `handle-props.ts:55` seam no longer
exists.
