# T1.7 — CI workflow

**Phase** P1 — Scaffold · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

The same gate the board demands locally — `bun run verify` — enforced on every push and
pull request, on the Node versions the published package claims to support.

## Test first

Not applicable — the workflow's own green run is the proof.

## Acceptance criteria

- `.github/workflows/ci.yml` runs on pushes to `main` and on pull requests.
- Uses `oven-sh/setup-bun@v2` (with a pinned bun version) for install and scripts.
  **No `pnpm/action-setup`, no `cache: pnpm`.**
- `bun install --frozen-lockfile` — CI must fail on a stale `bun.lock`, not silently resolve.
- Runs `bun run verify` as a single step, so CI and the local gate cannot diverge.
- Matrix over the Node versions in `package.json#engines` (22 and 24) via
  `actions/setup-node@v4` — Vitest and `tsc` run on Node, so the matrix is meaningful
  even though bun drives the scripts.
- No step invokes `bun test`.
