# T1.3 — `tsconfig.json` + `tsconfig.build.json`

**Phase** P1 — Scaffold · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

Two configs: one strict, no-emit config that typechecks `src` **and** `test`, and one
build config that emits `dist/` per-file, mirroring `src/` 1:1 with declarations and
maps. No bundler in the chain.

## Test first

Not applicable directly — verified by `bun run typecheck` in [T1.6](T1.6-install-green.md)
and by the emitted `dist/` in [T9.4](T9.4-build-and-package-checks.md).

## Acceptance criteria

`tsconfig.json`:

- `strict`, plus `noUncheckedIndexedAccess`, `noImplicitOverride`,
  `noFallthroughCasesInSwitch`.
- `module` and `moduleResolution` are `NodeNext` — this is what makes the `.js`
  extension on relative imports mandatory (a repo convention) and what makes the
  `exports` map authoritative for consumers.
- `verbatimModuleSyntax` and `isolatedModules` on — these enforce the type-only import
  style the standards require, and Biome's `useImportType` must agree with them.
- `jsx: "react-jsx"`, `target`/`lib` at ES2022 + DOM + DOM.Iterable.
- `noEmit: true`; `include` covers `src`, `test`, and `vitest.config.ts`.

`tsconfig.build.json`:

- Extends the base; `noEmit: false`, `declaration`, `declarationMap`, `sourceMap`.
- `outDir: "dist"`, `rootDir: "src"` — so `dist/` mirrors `src/` file-for-file and the
  `exports` map's `./dist/<stem>.js` paths resolve.
- `include: ["src"]`, excluding `src/**/*.test.ts(x)` so tests never reach the tarball.

## Where it stands

Not started. Earlier drafts of both files were removed before the initial commit; write
them fresh. One decision worth carrying over from those drafts: `"types": []` in the base
config is deliberate — it keeps stray ambient `@types/*` packages out of the global scope,
so a dependency can't silently widen the type surface.
