# T1.4 — `biome.json` + `vitest.config.ts`

**Phase** P1 — Scaffold · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

One linter/formatter (Biome) and one test runner (Vitest), configured so `bun run check`
and `bun run test` are the only two commands anyone needs — and so the ESLint/Prettier
files they replace are gone rather than lingering as a second, contradictory source of style.

## Test first

Not applicable directly — the config is proven by `bun run check` and `bun run test`
running clean in [T1.6](T1.6-install-green.md).

## Acceptance criteria

`biome.json`:

- Pinned to a 2.x `@biomejs/biome` devDependency (2.5.7 is current). **Verify the config
  schema against the version actually installed** — Biome changed `files.include`/`ignore`
  to a single `files.includes` list with `!` negation between majors, and moved import
  sorting from `organizeImports` to `assist.actions.source.organizeImports`. Write the
  config the installed version's `$schema` accepts; don't copy a v1 snippet.
- Formatter matches the style the deleted Prettier config encoded: no semicolons, single
  quotes, 100-column width.
- Ignores `dist/`, `coverage/`, `node_modules/`, `playground/dist/`.
- Import sorting (Biome's assist action) enabled, so `bun run check` is genuinely the
  single pass.
- **Rule-coverage check — do not assume, confirm against the installed version's rule
  list, and record the findings here:**
  - Type-only imports: `style/useImportType` (and its `useExportType` counterpart) must
    be on. `verbatimModuleSyntax` in [T1.3](T1.3-tsconfig.md) and the standards' import
    rules both depend on this; it is what replaces
    `@typescript-eslint/consistent-type-imports`.
  - React hooks: confirm what Biome offers in place of `eslint-plugin-react-hooks` —
    `correctness/useExhaustiveDependencies` and `correctness/useHookAtTopLevel` are the
    expected pair. The StrictMode invariant (perf invariant 8) and the effect-based
    registration in P4 are exactly the code these rules guard. **If coverage is
    materially weaker than the ESLint plugin's, say so here and raise it with the user
    rather than silently accepting the gap.**
  - Unused vars ignoring a leading `_` argument prefix.
  - `noExplicitAny` on — "never `any` anywhere" is a public API policy, not a preference.

`vitest.config.ts`:

- `environment: 'jsdom'`, `setupFiles: ['./test/setup.ts']`.
- `include` covers colocated `src/**/*.test.ts(x)` **and** `test/**/*.test.ts` — the
  harness has its own test ([T1.5](T1.5-test-harness.md)), and at [T1.6](T1.6-install-green.md)
  time it is the *only* test in the repo. An `src`-only include makes P1 unverifiable.

No ESLint or Prettier devDependency may appear in `package.json` — Biome replaces both,
and a leftover `eslint-config-prettier` is a sign someone reintroduced one.

## Where it stands

Not started, and starting from nothing. The `eslint.config.js`, `.prettierrc.json`,
`.prettierignore`, and `vitest.config.ts` files that used to sit on disk were all removed
before the initial commit — the first three for a toolchain that's gone, the fourth because
its `include` covered only `src/**` and would never have run the harness test (see the
criteria above). Nothing is installed either: `node_modules/` is absent, so the Biome
rule-coverage check must wait for [T1.6](T1.6-install-green.md)'s install.
