# T9.6 — Chrome QA and profiler capture

**Phase** P9 — Integration & verification · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

Drive the playground in a real browser — jsdom has no layout engine, so a green suite is
necessary and not sufficient — and capture the render-count numbers the blog post will
quote.

## Acceptance criteria

- Pointer **and** keyboard drags exercised on the sortable page and the tree page in a real
  Chrome session.
- Console clean throughout: no React warnings, no StrictMode complaints, no listener
  errors.
- A GIF recorded of the tree page showing drop-into vs drop-between and the depth
  indicator — named meaningfully, for the blog post.
- **React Profiler render counts captured as actual measured numbers**, ours vs dnd-kit,
  for a defined scenario (state the item count, the drag distance, and the number of
  boundary crossings, so the measurement is reproducible).
- Numbers written down here in "Where it stands", with the date and the scenario — they are
  the source [T10.5](T10.5-blog-post.md) cites, and **estimating them is not permitted**.
- Any disagreement with the asserted counts in [T7.4](T7.4-sortable-granularity-tests.md) is
  investigated, not averaged away.
