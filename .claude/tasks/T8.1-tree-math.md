# T8.1 — `src/tree.ts`: the tree math

**Phase** P8 — Tree drag-and-drop (the flagship) · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

The thing this library exists to do properly. Tree drag-and-drop is hard because "where
does this drop" has two answers at once — *into* a node or *between* two nodes — and
because a careless implementation happily drops a node inside its own subtree. The whole
answer here is **pure functions over plain data**: no React, no DOM, exhaustively testable
in milliseconds. Per [`ANALYSIS.md`](../ANALYSIS.md) § A2: every general-purpose library
reports a gesture relative to *one row* and stops; this module returns the resulting
**position** — `(parentId, index, depth)`, clamped against both neighbours, with cycles
unrepresentable. Nobody else crosses that line, and this file is where it is crossed.

Two decided semantics govern everything here (§ A7 D1, D2):

- **Position follows the drop point.** The gap you drop in, at the depth you indicated,
  *is* the `(parentId, index)`. No separate placement rule.
- **Any node can be a parent** — documents gaining a `children` array, not "folders".
  `canNest(candidateParent, active)` takes both nodes and defaults to always-true.

## Test first

This task is the one where test-first pays for itself most. Red tests before any
implementation, per function:

**`flattenTree(items, activeId?)`** → visible rows as `{ id, parentId, depth, index }`
(`index` = sibling index within the parent, not visible-row position), plus a reverse index
`Map<id, { parentId, index, depth }>` emitted from the same single walk — so `applyTreeDrop`
locates nodes in O(depth) rather than searching O(N). (Slate's `NODE_TO_PARENT` /
`NODE_TO_INDEX` pattern; a plain `Map`, **not** a `WeakMap` — string keys, per-drag,
discarded.)

- Collapsed subtrees are excluded.
- With an `activeId`, the active node **itself and its descendants** are excluded from the
  rows (§ A7 F4 — active-row-as-neighbour was a front-door cycle: `prev = active` at depth
  `active.depth + 1` is nesting into yourself). The two gaps around the active node's origin
  merge into one **no-op position**; test that projecting there and applying returns the
  original tree. Visual mounting of the active row (dimmed) is the consumer's business —
  the math list is what cycle prevention lives in.
- Depth and index are consistent with the source tree; empty tree returns an empty list.

**`projectTreeDrop(...)`** → `{ parentId, index, depth, mode } | null`:

- **Drop-into** when the pointer is in the middle band of a nestable row;
  **drop-between** when it is in a gap. Test the band boundaries explicitly. Non-nestable
  rows have a **two-band partition** (before/after halves, no middle); define and test the
  tie at the exact half boundary.
- `mode: 'into'` resolves to **index 0** of the target node (§ A7 D1: the drop point is
  adjacent to the parent row, and on an *expanded* parent, 'into' and the gap below it at
  `depth + 1` are the **same position** — assert that equality directly).
- In a between-gap, depth is projected from pointer X in `indentPx` steps.
- **Depth clamp is canNest-aware** (§ A7 F1): lower bound `next.depth`; upper bound
  `canNest(prev, active) ? prev.depth + 1 : prev.depth` — depth `prev.depth + 1` *is*
  nesting into `prev`, and must obey the same predicate as the into-band. Test both ends,
  and the motivating case: dragging far left past the first sibling must not adopt the
  following subtree.
- **The clamp interval can be empty → the projection is `null`/blocked** (§ A7 F2): the gap
  between a node and its own first visible child when `canNest(prev, active)` is false
  admits no legal position. Test it; the React layer hides the indicator, and a release
  there is an end-with-no-move, not a cancel.
- **Boundary gaps** (§ A7 F5): top gap (no `prev`) → depth pinned to `next.depth`; bottom
  gap (no `next`) → clamp `[0, canNest-aware max]`. Both tested.
- **Parent/index derivation from depth** (§ A7 F3): `depth = prev.depth + 1` → parent is
  `prev`, index 0. `depth ≤ prev.depth` → parent is prev's ancestor at `depth − 1` (via the
  reverse index, O(depth)), index = sibling-index of prev's ancestor-or-self at `depth`,
  plus one. When `next.depth === depth`, the result must equal "insert before `next`" —
  dedicated equality test.
- The projection never targets the active subtree (an invariant test over generated cases,
  not one example).

**`applyTreeDrop(items, activeId, projection)`**:

- **Immutable via structural sharing — not a deep clone.** Rebuild only the ancestor spines
  of the removal and insertion points; **return the identical reference for every subtree that
  did not change.** This is how Slate keeps editing cheap (one keystroke rebuilds ~5 objects,
  not the document), and it is what lets a consumer's `memo`'d rows bail out after a drop. A
  naive deep clone or `structuredClone` gives every node a fresh identity, so **every row
  re-renders** — on a 10k-node tree, 10k re-renders where ~2×depth would do. A deep clone is
  otherwise *correct*, which is why only an explicit identity test catches it:
  after a move, assert untouched sibling subtrees are `===` to their originals and that only
  the spine changed identity. The input array and its nodes are never mutated (assert on the
  original). See [`ANALYSIS.md`](../ANALYSIS.md) § A5.
- **A no-op projection returns the same `items` reference** (§ A7 F4) — structural sharing's
  degenerate case, tested.
- **Dropping into a childless node creates its `children` array immutably** (§ A7 D2); when
  the last child moves out, `children: []` is left behind, not deleted — documented
  behaviour, both directions tested.
- Same-parent moves adjust the index correctly when the removal precedes the insertion —
  the classic off-by-one, tested in both directions.
- Defensive cycle guard: a hand-crafted cycle-inducing projection is rejected rather than
  producing a corrupt tree, even though `flattenTree` should have made it unreachable.
- **Round-trip invariant:** `applyTreeDrop` then `flattenTree` puts the node at exactly the
  projected parent, index, and depth. This single property test covers more than any
  handful of examples. (A `null` projection never reaches apply — nothing to round-trip.)

## Acceptance criteria

- Exports `flattenTree`, `projectTreeDrop`, `applyTreeDrop`, and the tree types; subpath
  `fc-react-dnd/tree`.
- **The projection carries id-relative position, not only a slot index.** `projectTreeDrop`
  returns `parentId` (an id — safe) alongside `index` (a slot — not). `applyTreeDrop` receives
  the tree *as it exists at drop time*, which may differ from the one the projection was
  computed against: a concurrent edit, a lazy load, or the consumer's own state change can
  remove a sibling before the insertion point and shift every index after it. So the
  projection must also carry the neighbour it lands after/before, and **`applyTreeDrop` must
  resolve the final index from that neighbour against the tree it is handed** rather than
  trusting the captured number. Test it directly: project a drop, remove a preceding sibling,
  *then* apply, and assert the node lands next to the intended neighbour — not at the stale
  index. This is A5's "key by id, never by path" arriving from the concurrency side; see
  [`ANALYSIS.md`](../ANALYSIS.md) § A6.
- **Keyboard totality holds in the math** (§ A7 F9): with D1's index-0 rule, every legal
  outcome is expressible as a gap position at a legal depth — 'into' on a collapsed or
  childless nestable row is the deepest rung of the gap below it. The reachability *test*
  lives in [T8.2](T8.2-use-tree-drop.md)/[T5.2](T5.2-keyboard-sensor.md); this module must
  not make it impossible (no outcome reachable only by a middle-band point).
- **Pure** — no React, no DOM, no `'use client'`. Runs under plain Node.
- `indentPx` and the band fraction are named constants / options — no bare literals.
- No `any`; tree item generics carry the consumer's own node data.
- The invariants (never targets the active subtree; every projected depth within the
  canNest-aware clamp; apply→flatten round-trips; no-op returns same reference) each have an
  explicit test.
