# T9.4 — Build output and package checks

**Phase** P9 — Integration & verification · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

Prove the thing consumers install actually resolves. An ESM-only package with a
root-entry-less subpath `exports` map has exactly the shape that tooling gets wrong, so it
gets checked by machine rather than by reading the manifest.

## Acceptance criteria

- `bun run build` emits `dist/` mirroring `src/` 1:1 — `.js`, `.d.ts`, `.js.map`,
  `.d.ts.map` per module, and **no test files**.
- Every subpath in `package.json#exports` resolves to files that exist on disk.
- Nothing in `dist/` imports a package that isn't a peer dependency — zero runtime deps,
  verified rather than assumed.
- `'use client'` directives survive the `tsc` emit where they were in the source.
- `publint` clean.
- `attw --pack . --profile esm-only` clean — no false CJS, no masquerading types.
- **A deep import into `dist/internal/*` fails to resolve** from a consumer's perspective.
  This is ground rule 4 enforced by the module resolver; assert it, don't trust it.
- `bun run verify` green end to end.

## Files

- No new source files — this task verifies the output of the others. Any fix it forces
