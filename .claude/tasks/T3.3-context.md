# T3.3 — `src/internal/context.ts`

**Phase** P3 — Store & subscription layer · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

Carry the per-provider store handle down the tree — and nothing else. The context value
must be **stable for the provider's lifetime**, because a changing context value would
re-render the entire subtree on every drag and undo the whole architecture.

## Test first

Red tests before implementation:

- A consumer outside any `DndProvider` gets a clear, named error — not
  `undefined is not an object` from three frames deeper.
- The context value is referentially stable across provider re-renders (assert identity
  across a forced parent re-render). This is the test that protects perf invariant 4.
- Two sibling providers hand their subtrees two different stores — no cross-talk.

## Acceptance criteria

- Context carries the store handle only; drag state is read through
  [T3.2](T3.2-use-store-selector.md), never through context.
- A small `useDndStore`-style accessor throws a named, actionable error when used
  outside a provider.
- `'use client'` at the top (it touches React context).
- No module-level store — SSR-safe and multi-provider-safe by construction.
