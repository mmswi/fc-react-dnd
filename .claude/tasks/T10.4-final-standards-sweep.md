### Three findings, all fixed

**1. `mergeActivators` was implemented twice**, identically, in `use-draggable.ts` and
`use-tree-drop.ts` — and so was the whole `handleProps` object they both hand out. That second
one is the dangerous half: an accessibility attribute present on one and not the other is exactly
the divergence nobody notices until a screen-reader user does. Both now come from
`src/internal/handle-props.ts`.

**2. `ESCAPE_KEY` was declared twice**, in both sensors. Two symbols that happen to spell alike;
a rename touches one. Now `src/internal/keys.ts`, along with `DRAG_ACTIVATION_KEYS`.

**3. Perf invariant 2 had no test — and was being violated.** Writing the missing test found a
real read-after-write in the auto-scroll loop: `container.scrollLeft += intent.x` is a
read-modify-write, so reading `scrollTop` for the second `+=` happens *after* the `scrollLeft`
write. A layout read interleaved with a layout write, every frame of every drag. Both writes now
come from the offsets already read in the single metrics batch, and the test asserts the
**ordering** — last read before first write — rather than merely that scrolling happened.

### `'use client'`, on one uniform line

The rule as applied: **directive-free iff the module has no browser and no React-runtime
dependency at all** — pure functions over plain data. Everything else carries it.

- **Directive-free — 9 of 27 modules:** `types`, `collision`, `tree`, `internal/geometry`,
  `internal/announcements`, `internal/list-projection`, `internal/tree-projection`,
  `internal/keys`, `internal/handle-props`. All six the criteria name are here.
- **Moved to the client side during this sweep:** `internal/dom` and `internal/store`, because
  both hold and read DOM nodes. `internal/handle-props` went the other way — it was created with
  the directive and does not need it: no DOM, no React runtime, just an object built from values
  it is handed.
- Verified from the **emitted** `dist/`, not the source: every directive-free module's JS imports
  only other directive-free modules. `internal/list-projection` emits **no runtime imports at
  all** — its `DragStoreState` import is type-only and fully erased.
