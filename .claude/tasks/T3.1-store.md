# T3.1 — `src/internal/store.ts`

**Phase** P3 — Store & subscription layer · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

The heart of the library: a plain external store holding all drag state, created **per
`DndProvider` instance** — never module-level, so it is SSR-safe and multi-provider-safe.
This is where the central performance claim is either true or false: rects are measured
once at drag start and every subsequent move is pure arithmetic against the cache.

## Test first

The store is synchronous by design and needs no React and no frame control, so it can be
driven directly. Red tests before implementation, one behaviour at a time:

- **Registration never notifies — while idle.** Subscribe, register and unregister a
  draggable and a droppable with no drag active, assert the subscriber was called zero times
  (perf invariant 5).
- **But registration during a drag is a structural event, and the policy is asymmetric**
  (decided 2026-08-08, [`ANALYSIS.md`](../ANALYSIS.md) § A6):
  - **Unregistration cancels.** Unregister *any* droppable or draggable mid-drag — the active
    one, the current `over`, or an unrelated row above it — and assert the drag cancels via
    the cancel path (not the end path), transforms reset, `onDragEnd` does **not** fire, and
    teardown is complete. The unrelated-row case matters most: it is the one that would
    otherwise resolve silently against a stale rect cache and produce a wrong drop with no
    error anywhere.
  - **Registration does not cancel.** Mount a droppable mid-drag and assert rects are marked
    dirty, re-measured, and collision re-runs — with the drag still alive. Cancelling here
    would break tree auto-expand-on-hover and lazy-loading lists.
- The cancel path must carry **why** it fired, so `onDragCancel` can distinguish a user's
  Escape from a forced cancel (see [T4.1](T4.1-dnd-provider.md)).
- **Rects measured once.** Count measurement calls across `beginDrag` + N `updateDrag`
  calls; assert measurement happened once, not N+1 times (perf invariant 1).
- **Dirty flag.** After a scroll/resize signal, the next update re-measures — and only
  the next one.
- **Stale session token.** A `DragSession` captured before `endDrag` becomes a no-op
  afterwards: calling `move` / `setTransform` / `end` on it changes nothing and notifies
  nobody.
- **Events fire before state reset.** An `onDragEnd` listener reading active/over during
  the callback sees the drag that just ended, not a cleared state. Same for cancel.
- **Monitor fan-out** reaches every listener; unsubscribing one leaves the others intact.
- **Immutable state object** — every notifying transition produces a new state reference,
  which is what makes the WeakMap memoization in [T7.1](T7.1-list-projection.md) and
  [T8.2](T8.2-use-tree-drop.md) sound.

## Acceptance criteria

- A factory function, not a class (per the standards).
- Registries for draggables and droppables; register/unregister mutate without notifying.
- **A third registration kind: measure-only** (§ A7 D3/F7 in [`ANALYSIS.md`](../ANALYSIS.md)).
  Tree rows register rects for the cache and for keyboard targeting but are **excluded from
  collision** — `closestCenter` never sees them, and they never produce `over`. Internal
  only (reached through `useTreeDrop`'s `getRowProps`, not `useDroppable`). They still count
  as registered nodes for the A6 removal-cancels policy.
- **The mid-drag structural path mints a new state version even when `over` is unchanged**
  (§ A7 F6): an insertion re-measures and re-collides, and *must* produce a new state object
  so per-drag derived projections recompute — subscribers whose slices are unchanged still
  don't render (A3.1 gate 1), so this is cheap. Assert: register a droppable mid-drag with
  `over` unchanged, and the state object identity still changes.
- Lifecycle: `beginDrag`, `updateDrag`, `endDrag`, `cancelDrag`.
- `DragSession` handed to sensors on activation, guarded by a session token so a stale
  session cannot resurrect a finished drag.
- Droppable-rect cache: batched reads at `beginDrag`, re-measured lazily via the dirty
  flag — **no DOM reads in the move path** (perf invariant 1, 2).
- Collision runs against the cache on every move, with disabled droppables filtered here
  (the boundary [T2.3](T2.3-collision-closest-center.md) deliberately leaves to the caller).
- Complete teardown on end/cancel — no per-interaction state survives (perf invariant 7).
- Named constants for any tunable; no `any`.
- **Know the tearing-recovery cost before designing the notify path.** Mutating an external
  store during a concurrent render makes React discard it and re-render the whole tree
  *synchronously* — `renderRootSync`, with the comment *"A store was mutated in an
  interleaved event. Render again, synchronously, to block further mutations"*
  (`ReactFiberWorkLoop.js:1151-1173`). This library mutates the store on every pointermove,
  which is exactly that case. Mitigating detail: the check is skipped for blocking lanes
  (`ReactFiberHooks.js:1691`) and recovery runs only `if (renderWasConcurrent)`, so
  discrete-input drags aren't exposed — a concurrent render in flight elsewhere in the app
  is. See [`ANALYSIS.md`](../ANALYSIS.md) § A3.3, which also proposes measuring it.
