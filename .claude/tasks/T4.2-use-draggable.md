# T4.2 — `src/use-draggable.ts`

**Phase** P4 — React API · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

Turn any element into a drag source: a ref to register the node, `handleProps` to spread
on the handle, and the two pieces of state a consumer actually renders from — `isDragging`
and `transform`.

## Test first

Red tests before implementation:

- **Selector granularity.** A draggable that reads only `isDragging` re-renders on drag
  start and end — and **not once per pointermove**. Render counter across a 20-move drag
  asserts the exact count (perf invariant 4). The inverse case: a draggable that *does*
  select `transform` re-renders per move, and only the active one does.
- Registration happens in an effect, notifies nobody, and unregisters on unmount; clean
  under StrictMode (perf invariants 5, 8).
- `handleProps` merges the activators of **all** configured sensors — adding a second
  sensor must not silently drop the first one's listeners.
- A consumer's own `onPointerDown` passed through `handleProps` still fires alongside the
  sensor's.
- Disabled: keeps `aria-disabled`, loses activation listeners, and a pointerdown starts
  nothing (accessibility invariant 4).

## Acceptance criteria

- Exports `useDraggable`, `UseDraggableOptions`, `UseDraggableResult`; subpath
  `fc-react-dnd/use-draggable`.
- `handleProps` carries `role="button"`, `tabIndex={0}`, `aria-roledescription`,
  `aria-describedby` → the instructions element, `touch-action: none`, and
  `draggable={false}` (accessibility invariant 3).
- `data` is `Record<string, unknown>` and reaches the drag events unchanged.
- No DOM measurement in the hook — rects are the store's job.
- `'use client'` at the top.
