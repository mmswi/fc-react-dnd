# T6.1 — `src/drag-overlay.tsx`

**Phase** P6 — Overlay, auto-scroll, accessibility · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

An element that follows the pointer with **zero React renders per move**. It subscribes to
the store outside React's render cycle and writes `style.transform` directly to its own
node inside `requestAnimationFrame`. This is the most visible piece of the performance
argument in the blog post.

## Test first

Red tests before implementation, with `vi.useFakeTimers({ toFake: ['requestAnimationFrame'] })`
and `nextFrame()` from [T1.5](T1.5-test-harness.md):

- **Zero renders per move.** Render counter on the overlay's children; drive 20 moves;
  assert the count is 1 (perf invariant 3, 4). Without this test the optimisation can
  regress invisibly.
- **rAF coalescing.** Three moves inside one frame produce exactly **one** `transform`
  write, carrying the latest position — not three writes, not a stale one.
- Positioned `fixed` at the active item's `initialRect` from the store, so it starts
  exactly over the source element.
- `pointer-events: none` — a droppable underneath the overlay is still hit-testable
  (assert via collision, since jsdom won't hit-test for us).
- Renders nothing when no drag is active; unmounts on drop and cancels its pending frame.
- Portals to `document.body`.

## Acceptance criteria

- Exports `DragOverlay` + `DragOverlayProps`; subpath `fc-react-dnd/drag-overlay`.
- Motion is `transform` only — no `top`/`left` writes (perf invariant 3).
- One rAF write per frame maximum; the pending frame is cancelled on unmount and on drop
  (perf invariant 7).
- `'use client'` at the top.
- Drop animation is explicitly **out of scope** (Backlog).

### Two subscriptions, deliberately

- `useStoreSelector` on `state.origin` — whose identity survives every move — so React mounts
  the overlay on drag start and unmounts it on drop, and does nothing in between.
- A **raw `store.subscribe`** inside an effect for the motion, writing `style.transform`
  directly to the node inside `requestAnimationFrame`. The pointer stream never reaches the
  reconciler at all.

The children render **once** for a whole drag; asserted across twenty moves.

### rAF coalescing is asserted two ways, because one of them alone would be weak

- Three moves inside one frame schedule **exactly one** `requestAnimationFrame` (spied).
- When that frame runs, the transform carries the **latest** position (99, 77), not the first
  of the batch — and a separate test confirms nothing is written *before* the frame runs.

Together those say what perf invariant 3 actually claims: at most one style write per frame,
always carrying the newest position.

### Motion is transform-only

`top`/`left`/`width`/`height` are set once from `origin.rect` when the overlay mounts and are
asserted **unchanged** after a move — only `transform` changes. `pointerEvents: 'none'` is on
the base style rather than merged from props, so a consumer's `style` cannot accidentally
remove it and make the overlay swallow its own drop.

### Teardown

The effect's cleanup unsubscribes and cancels any pending frame — both asserted, the second by
spying on `cancelAnimationFrame`. A separate test starts a *second* drag after the first ended
and checks the overlay works, which is what a stale subscription writing to an unmounted node
would break.
