# T0.1 — `CLAUDE.md`, the project constitution

**Phase** P0 — Governance · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

One document a fresh session can read cold and know what this project is, what it
refuses to do, and how to work it: scope, ground rules, toolchain, commands,
architecture, the module map, and the performance/accessibility invariants that
reviews cite by number.

## Test first

Not applicable — documentation, no code. Ground rule 2 (`tdd`) applies from P2 on.

## Acceptance criteria

- Ground rules are numbered and non-negotiable, and include both mandatory skills:
  `mihai-coding-standards` (rule 1) and `tdd` (rule 2).
- Task workflow points at `.claude/TASKS.md` + `.claude/tasks/`, and states that
  status lives only in the TOC.
- Commands table is bun-based and warns that `bun test` is not `bun run test`.
- Performance invariants are numbered 1–9 so reviews can cite them.
- Public API policy, repo conventions, testing notes, and the release checklist are present.
- No stale references to pnpm, ESLint, or Prettier anywhere in the file.
