# T2.1 — `src/types.ts`, the shared public type surface

**Phase** P2 — Core primitives · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

The vocabulary every other module speaks. Types only — no runtime code, no `'use client'`,
so this module stays server-importable. Getting these names right early is cheap;
renaming a public type in P8 is an API decision with a task of its own.

## Test first

Types have no runtime behaviour to red-test. The equivalent discipline: write the
type-level assertions first — a `src/types.test-d.ts`-style file (or `expectTypeOf` in a
regular test) that pins the shapes consumers depend on, so a later widening is caught by
`bun run typecheck` rather than by a consumer.

## Acceptance criteria

- `DndId` (`string | number`), `Translate` (`{ x, y }`), `Rect`.
- `DndData` = `Record<string, unknown>` — never `any`, per the public API policy.
- Active and over shapes (`{ id, data, rect }`-ish), carrying the data payload through
  to callbacks.
- Drag event types: start, move/over, end, cancel — each naming what a consumer actually
  needs, with `over` nullable.
- **`DragCancelReason`**, exported, as a string-literal union:
  `'escape' | 'blur' | 'pointer-cancelled' | 'item-removed'`. The cancel event carries it.
  `'item-removed'` is the library forcing a cancel because a registered node disappeared
  mid-drag ([`ANALYSIS.md`](../ANALYSIS.md) § A6); `'pointer-cancelled'` is the browser taking
  the interaction away via `pointercancel` ([T5.1](T5.1-pointer-sensor.md)). Consumers branch
  on this, so it is public API — a union member added later is a breaking change for anyone
  who wrote an exhaustive `switch`.
- `CollisionDetection` plus its args type — the seam that keeps custom strategies
  pluggable even though the library ships exactly one ([T2.3](T2.3-collision-closest-center.md)).
- `Sensor` contract: what the provider hands a sensor, and the `DragSession`
  (`move` / `setTransform` / `end` / `cancel`) a sensor drives during one interaction.
- Announcement types for the accessibility layer ([T6.3](T6.3-accessibility-internals.md)).
- Every exported name is unique package-wide; no `Props` shorthand on exported types.
- No `any`. No runtime values exported from this file.
- **First green `bun run verify` in the project.** This is the task that puts a file in
  `src/`, so it is the first point at which `bun run build` has an input and the full gate
  can pass — see the note in [T1.6](T1.6-install-green.md).

## Where it stands

`src/types.ts` + `src/types.test.ts` on disk (2026-08-08). **First green `bun run verify`
in the project** — typecheck, Biome, 25 tests, build, publint, and attw all clean.

The type assertions are enforced by `bun run typecheck`, not at runtime: `expectTypeOf`
erases, so a widened public shape fails the gate rather than passing a green test. That was
confirmed the hard way — a bad assertion in the first draft failed `tsc` while the test run
reported 16 passing.

### Three amendments this task forced, each a deliberate departure from the criteria above

**1. `types.ts` exports two `const` objects, so "no runtime values" no longer holds
literally.** `DRAG_CANCEL_REASONS` and `DRAG_DIRECTIONS` are runtime values. The criterion
was protecting *purity* — no DOM, no React, no side effects, server-importable — and a
frozen record of string literals keeps all of that. What it cannot survive is the standards'
"no bare literals in logic" rule: a union type alone leaves every consumer writing
`reason === 'item-removed'`, unguarded by the compiler against `'item-remvoed'`. The type
still derives from the constant, so there is one source of truth. `dist/types.js` is
therefore a real module rather than an empty file, and resolves cleanly.

**2. `DragSession` has a fourth member, `findTargetInDirection`.** [`ANALYSIS.md`](../ANALYSIS.md)
§ A9.1 froze it at `move` / `end` / `cancel`; A9.1 is amended in place with the reason. The
keyboard sensor has to answer "what is the next droppable upward?", and the only two ways to
give it that are a geometry query on the session or a public rect cache. The query keeps
perf invariant 1 true for the keyboard path — the sensor never reads the DOM — and keeps the
measure-only-rows rule ([T3.1](T3.1-store.md)) an internal detail rather than something every
sensor author has to know about.

**3. `package.json#exports` now grows one entry per task instead of listing all fourteen up
front.** `publint` failed `verify` with 26 errors — every subpath pointing at a `dist/` file
that does not exist yet — and it was right to. An exports map is a promise about what
resolves; making that promise thirteen modules early is a manifest that lies. Each remaining
module adds its own entry in its own commit, which is also what the API policy describes
("adding a subpath is an API decision → its own task"). [T9.4](T9.4-build-and-package-checks.md)
checks the complete map against `CLAUDE.md`'s module map at the end.

### Shapes worth knowing before reading any other module

- `Point` and `Translate` are declared separately despite being structurally identical.
  Conflating "where the pointer is" with "how far it has moved" is a real bug, and two names
  make it unspellable in a signature.
- `Rect` is `{ top, left, width, height }` — no `right`/`bottom`. They are derivable, and a
  rect that carries them can be constructed inconsistent with itself.
- `SensorActivatorProps` covers exactly `onPointerDown` and `onKeyDown` — the two sensors in
  scope. Adding a third is a public API decision, deliberately.
- Provisional until P5: the `Sensor` / `DragSession` / collision shapes are genuinely
  discovered while writing [T3.1](T3.1-store.md) and [T5.1](T5.1-pointer-sensor.md). Nothing
  is published, so refining them during initial construction is construction, not an API
  change needing a ceremonial task per tweak.
