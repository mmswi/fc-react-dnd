# T9.5 — `playground/` Vite app

**Phase** P9 — Integration & verification · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

The demo, and the instrument that produces the blog post's numbers. Three pages, all
inside `<StrictMode>`, all aliased straight at `src/` so there's no build step between a
change and seeing it.

## Acceptance criteria

- A workspace package under `playground/`, resolved through
  `"workspaces": ["playground"]` in the root `package.json` ([T1.2](T1.2-package-json.md)).
  Its `package.json#name` is **`playground`** — `bun run --filter` matches the package
  *name*, not the directory, and `CLAUDE.md` § Commands documents
  `bun run --filter playground dev`. A different name silently breaks that command.
- Vite config aliases `fc-react-dnd/*` → `../src/*`, so the playground exercises source,
  not `dist/`.
- Every page wrapped in `<StrictMode>` — the StrictMode-clean claim is demonstrated, not
  asserted (perf invariant 8).
- **Sortable page** — a list with a per-component render counter on each item, wrapped in
  React `<Profiler>`.
- **Tree page** — drop-into vs drop-between indicator, live depth readout, and a
  cycle-prevention case a visitor can try (drag a parent onto its own child and watch it
  refuse). Any document can be a parent (§ A7 D2) — the fixture is a doc tree, not a
  folders-and-files tree. Demonstrates the **auto-expand recipe** (§ A7 F8): hover a
  collapsed node to expand it mid-drag, collapse state restored in `onDragEnd`/`onDragCancel`
  — never mid-drag. Announcements on this page are projection-driven and audible via the
  live region ([T8.2](T8.2-use-tree-drop.md)).
- **Comparison page** — the same sortable list built with `@dnd-kit/*` next to ours, with
  identical render counters, so the numbers are like-for-like. Use **classic dnd-kit**
  (`@dnd-kit/core` 6.3.1 + `@dnd-kit/sortable`) — that is what people actually ship. The
  rewrite (`@dnd-kit/react` et al.) was at 0.5.0 and pre-1.0 as of 2026-08-07; benchmarking
  against an unstable pre-release would be both unfair and unreproducible. Record the exact
  version used, since the comparison is only meaningful against a pinned target.
- **`@dnd-kit/*` appears only in `playground/package.json`** — never in the root manifest.
  This is a repo convention with teeth; a root-level dnd-kit dependency invalidates the
  whole comparison.
- The playground is not published (`private: true`, excluded from the tarball).

## Where it stands

`playground/` on disk (2026-08-08): `package.json` (name **`playground`**, `private: true`),
`vite.config.ts`, `index.html`, `tsconfig.json`, and five source files. `bun run --filter
playground build` succeeds; `bun run verify` at the root stays green and Biome covers the
playground too.

The Vite alias maps `fc-react-dnd/<subpath>` → `../src/<subpath>`, so the demo exercises
**source**, not `dist/`. Vite resolves the repo's NodeNext `.js` specifiers back to `.ts` without
help, which is worth knowing because it is the one thing that could have forced a plugin.

Every page is inside `<StrictMode>` — `main.tsx` wraps the whole app — so the StrictMode-clean
claim is demonstrated rather than asserted.

### The three pages

- **Sortable** — 24 rows, each with a commit badge and a `<Profiler>` around the list. Drag one
  row past another and only three badges move. `onSortEnd` is echoed as JSON, including the
  id-relative landing position.
- **Tree** — a **document** tree, not folders (§ A7 D2): any document gains a `children` array
  when something is dropped on it. Drop-into versus drop-between indicators, a live projection
  readout, and two things a visitor can try — dragging a document onto its own child (refused,
  because the active subtree is never offered rather than being rejected afterwards) and
  *On-call*, which declines children, so the depth stops a level short beside it. The § A7 F8
  **auto-expand recipe** is implemented here: hover a collapsed node for 600 ms to expand it
  mid-drag, and collapse state is restored only in `onDragEnd`/`onDragCancel`.
- **Comparison** — the same 24-row list built twice with identical commit counters. Baseline
  recorded on the page itself: `@dnd-kit/core` **6.3.1** + `@dnd-kit/sortable` **10.0.0**, the
  classic packages people actually ship rather than the pre-1.0 rewrite.

`@dnd-kit/*` appears **only** in `playground/package.json` — checked, not assumed.

### Three defects fixed while building it, all in the demo rather than the library

- **The tree page had no `DndProvider`.** `useTreeDrop` would have thrown its named
  out-of-provider error the moment the page opened. Caught by Biome's `noUnusedImports` flagging
  the imported-but-unrendered `DndProvider` — a lint rule finding a runtime bug.
- **Auto-expand started its timer during render.** Under StrictMode that runs twice and leaks the
  first timer. Moved into an effect keyed on the hovered parent.
- **`hasChildren` re-flattened the whole tree per row**, inside the render loop. Replaced with a
  single walk that builds the title map and the has-children set together.

### The commit counter counts commits, deliberately

`useCommitCounter` increments in an effect with no dependency array, not in the component body.
A body counter ticks on a render React runs and discards through its late bailout, and these
numbers have to mean the same thing as [T7.4](T7.4-sortable-granularity-tests.md)'s and as the
React Profiler's in [T9.6](T9.6-chrome-qa-and-profiler.md).
