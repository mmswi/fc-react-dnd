# T1.6 — Empty-green: install, typecheck, check, test

**Phase** P1 — Scaffold · **Board** [`.claude/TASKS.md`](../TASKS.md) (status lives there)

## Goal

Prove the toolchain works *before* any library code exists, so the first red test in P2
fails for a real reason rather than because a config is wrong.

## Test first

This task **is** the test — of the toolchain rather than of the library.

## Acceptance criteria

- `bun install` completes clean and writes a `bun.lock` (committed).
- `bun run typecheck` exits 0.
- `bun run check` exits 0 (Biome finds nothing to fix in the repo's own files).
- `bun run test` exits 0 — the harness test from [T1.5](T1.5-test-harness.md) passes;
  no "no test files found" error.
- **`bun test` is not used anywhere.** Confirm the distinction holds by observing that
  bare `bun test` behaves differently, and that no script, doc, or CI step invokes it.
- Findings from [T1.4](T1.4-biome-and-vitest-config.md)'s Biome rule-coverage check are
  recorded in that task's "Where it stands" once the install makes them checkable.

**Deliberately *not* in scope here: `bun run build` and `bun run verify`.**
`tsconfig.build.json` has `include: ["src"]`, and `src/` does not exist yet — `tsc` errors
`TS18003: No inputs were found in config file` when an include matches nothing, so `build`
(and therefore `verify`) cannot pass until [T2.1](T2.1-public-types.md) puts a file in
`src/`. Confirm that behaviour when running this task; if `tsc` turns out to tolerate the
empty include, add both commands back to the criteria above. **The first green
`bun run verify` is an acceptance criterion of [T2.1](T2.1-public-types.md)**, not of this task.

## Where it stands

Green on 2026-08-08. `bun install` clean and `bun.lock` committed; `bun run typecheck`,
`bun run check`, and `bun run test` (9 tests) all exit 0.

**The `bun test` distinction was confirmed by running it, not by citing the docs.** Bare
`bun test` on the same suite: `0 pass, 9 fail`, failing with `ReferenceError:
requestAnimationFrame is not defined` — Bun's runner ignores `vitest.config.ts`, so there is
no jsdom environment, no `test/setup.ts`, and no faked rAF. It is the failure mode CLAUDE.md
warns about, and it looks exactly like a product bug. No script, doc, or CI step invokes it.

`bun run build` fails with `TS18003: No inputs were found in config file` while `src/` is
empty, exactly as this task predicted, so `build` and `verify` stay out of scope here.
[T2.1](T2.1-public-types.md) owns the first green `bun run verify`.
